# Review round 1: AI-agent failure modes (A) and structural biophysics / med-chem (B)
Reviewer: agents/biophys reviewer, 2026-10-26. Reviewed: DESIGN.md v0, PROMPT.md, AGENTS_BRIEF.md, LESSONS.md, reports/*.md.
Priorities: P0 = must fix before any val number is trusted; P1 = before freeze; P2 = nice to have. Nothing below has been run; it is design critique only.

## A. AI-agent failure modes and guards
A1 (P0) **Crystal-ligand leakage via the input files.** Likely ways it happens: (i) the receptor PDB still holds the query ligand or its altlocs as HETATM; (ii) the ETKDG start pose is placed at crystal coordinates, or the "SMILES/graph" path reads the crystal SDF *with coordinates*; (iii) holo waters or ions placed by the ligand are kept; (iv) PDBFixer/reduce H-flips are run with the ligand present. Guard: one `src/adock/io/inputs.py::make_docking_inputs()` used by ours AND the baselines. It strips every non-polymer except an explicit allow-list (see B3) and re-embeds the ligand from a canonical SMILES (coordinates dropped). It randomises the start pose with a seeded random rotation and a centroid placed uniformly in the box. Then `scripts/check_inputs.py` asserts: no receptor heavy atom within 1.0 Å of any crystal-ligand atom position; the input ligand's RMSD to the crystal pose is > 2 Å (record the distribution); and the ligand file has no conformer flagged 3D-from-crystal. Run it on every input set and fail hard.
A2 (P0) **Box and centroid exploitation (reward hacking).** A box centred on the crystal-ligand centroid with a tight +8 Å padding gives every method a strong prior. The risk is that our engine adds a centroid restraint, a "distance to box centre" term or a box-shaped penalty, and wins because of it. Guard: the engine API receives only (center, size), and a unit test checks that the score does not depend on the box centre once a pose is inside the box. Also report a sensitivity run on val with the box centre taken from the pocket residues (centroid of residues within 6 Å, as a pocket finder would supply it) and a ±2 Å jitter, for all methods.
A3 (P0) **RMSD bugs.** Atom order differs between the SMILES-built ligand and the crystal SDF. H and protonation change the graph, so spyrmsd graph matching fails or silently matches a wrong isomorphism. Superposing the ligand before RMSD (spyrmsd `minimize=True`) gives tiny numbers. Guard: `scripts/tests/test_rmsd.py` with known answers: a permuted copy gives 0; a 3 Å rigid translation gives 3.000; a symmetric ligand (benzene, carboxylate) flip gives 0; and `minimize=False` is asserted in code. Per complex, assert that the heavy-atom element multisets match and that bond-graph isomorphism succeeds. A failed match is an error that gets logged, never a NaN that is dropped. Cross-check 20 val complexes against the PoseBusters `rmsd` module (target: identical to 1e-3 Å).
A4 (P0) **Denominator shrinkage.** Timeouts, crashes, RMSD errors and complexes with no AFDB model drop out silently, which raises the success rate. Guard: every metric is computed over the locked ID list in `results/splits/*.csv`. Missing or timeout counts as failure (pose = none). Every table prints n_total, n_missing and n_timeout per method. Use one identical per-complex wall-clock limit for all methods (e.g. 120 s) and record it in config.
A5 (P0) **Silent test access.** The PDB mirror makes test structures trivially reachable, so a guard cannot be physical. Guard: one loader `load_split(name)` raises an error for `test*` unless `ADOCK_FINAL_EVAL=1`, and appends each access (time, caller, git hash) to `logs/test_access.log`, which is committed. `scripts/audit_test_access.sh` greps results/, logs/ and scratch/ for test IDs and runs at every milestone. PB-V2 / RnP / PLINDER-test IDs are a blacklist in every val/fit script.
A6 (P0) **Val is contaminated by test homologues.** The design filters train against test, but not val. PLINDER-val, Astex and DockGen-val overlap PB-V2 targets (target overlap likely, e.g. kinases/proteases; not yet measured), so model selection on val tunes to test proteins. Guard: apply the same UniProt/cluster filter to val, or report val both with and without the overlap; select on the filtered val.
A7 (P1) **Overfitting to val through many variants.** 6 AF arms × combinations × weight fits × search settings can easily give 100+ looks at val. Guard: (i) an append-only `results/val_runs.tsv` (variant, config hash, commit, n, success, CI), written by the eval script and not by agents; (ii) split val into **val-select** (PLINDER-val) and **val-confirm** (Astex + DockGen-val, or a 30 % held-back slice), and confirm the frozen config on val-confirm exactly once before test; (iii) report the number of variants tried in REPORT.md.
A8 (P0) **Inconsistent preprocessing between ours and the baselines.** The smoke test used obabel PDBQT for the baselines, and ours will use its own typing. Guard: one prep script writes the receptor PDB (with H), the ligand SDF (with H, protonated, start pose) and the box JSON per complex, with a sha256 manifest. Baselines convert from these files only (meeko/obabel step logged), and the eval script asserts that every method's manifest hash is the same.
A9 (P1) **Factorial for C1.** If A4 (co-folding prep) wins, it is unclear whether the gain comes from the receptor or from the engine. Guard: run the best baseline (GNINA-no-CNN/Vina) on our AF-mode receptors too, and report a 2×2 (engine × receptor prep). Also report Boltz-2's own co-folded ligand pose as a reference arm, since it is the obvious competitor once co-folding is in the pipeline.
A10 (P1) **Timing claims under contention.** The smoke-test load was 28–41 on 16 cores, so timings are noise. Guard: `scripts/bench_timing.sh` takes an flock on `/tmp/adock/gpu.lock` plus an exclusive "timing window" announced in reports/, pins cores with taskset, runs warm (binaries on /tmp), takes the median of 3 repeats, records load average and nvidia-smi before and after, and refuses to run if loadavg > 4. Accuracy runs and timing runs are separate.
A11 (P1) **Env and result loss on /tmp at job end.** Guard: `scripts/bootstrap_node.sh` (all envs, binaries, Boltz cache, extracted data), followed by `check_env_*.py` and a 3-complex smoke test, which is the first command of every agent. Results, poses (tar/npz) and logs are written to <SHARED_WORK_FS> immediately and never only to /tmp. A checkpoint/resume flag goes in every batch script (skip done IDs).
A12 (P0) **Unverified success claims by agents.** Guard: a [!] or [x] entry in RESEARCH_TREE needs (command, commit, output path, n, CI) plus a sign-off line from a different agent, who re-computes the headline number from raw poses with `scripts/score_poses.py`. Keep the score/eval code read-only for engine-building agents (separate owner).
A13 (P1) **Seeds × McNemar ambiguity.** "Mean over 3 seeds" combined with "McNemar on per-complex success" is not defined. Pre-register: the primary statistic is seed 0, with seeds 1–2 reported for variance; or use a paired bootstrap over complexes with per-complex success averaged over seeds. `gap_closed` has a possibly tiny denominator: report it with a bootstrap CI and only if S_base,holo − S_base,AF ≥ 10 points.
A14 (P2) **Superposition frame.** The AF→holo superposition uses pocket residues selected by the crystal ligand. This is acceptable because the pocket is given, but it must be applied identically to all methods and arms, with a test that the transformed receptor's internal geometry is unchanged.

## B. Biophysics / medicinal chemistry
B1 (P0) **Ligand protonation/tautomers.** "Protonation as given" = CCD neutral (biotin COOH stays neutral in the smoke test). This corrupts H-bond donor/acceptor typing and any electrostatics/metal term. Change: protonate at pH 7.4 with one deterministic tool (dimorphite-dl or OpenBabel -p 7.4, pinned) for ours and the baselines alike. Variant: dock ≤ 3 protomers/tautomers as extra batch items and take the best score (cheap on GPU). Receptor: PDBFixer at pH 7.4 is fine; add PROPKA His states as a variant, prepared without the ligand present.
B2 (P0) **Covalent ligands** must be excluded from fit/val/test (PB-V2 selection should exclude them, verify; check RnP and PLINDER via the `ligand_is_covalent` annotation) and the count reported. Stratify by **multi-ligand** systems (other ligand within 6 Å).
B3 (P0) **Cofactors and metals in holo receptors.** Keep metal ions and cofactors/prosthetic groups (heme, NAD(P), FAD, FMN, SAM, PLP, ATP/ADP+Mg, Fe-S, Zn) that contact the pocket as receptor atoms. Remove all waters, buffer molecules and crystallisation additives (from a CCD allow-list/deny-list file, not hardcoded). Document this as one rule shared by all methods, and add a stratum "metal/cofactor within 6 Å of ligand" to every table. Compute this fraction for PB-V2/RnP now (my guess is 20–30 %; this needs measuring).
B4 (P0) **AF models lack metals/cofactors. This is a major, under-discussed part of the apo gap.** In an empty cofactor site, docking often puts the query ligand into the cofactor cavity or lets side chains collapse. Copying the cofactor from the *same* crystal is leakage in AF mode (there is no crystal at proteome scale). Options, in order: (a) **co-fold with cofactors/ions** (Boltz-2 accepts CCD codes and ions), with the cofactor identity taken from **UniProt annotations** (cofactor/binding-site fields, fetched by script). This scales to the AFDB, so make it the default AF-mode prep; (b) **AlphaFill-style transplant** from homologues, with donors restricted to non-identical UniProt entries released before the test date, excluding the test PDB entry and its cluster; (c) none (control). Report the AF-mode result with and without (a)/(b), and on the "has metal/cofactor" stratum separately. Add the metal-coordination term (ideal distance + rough geometry, e.g. Zn–N/O 2.0–2.2 Å) only if this stratum is ≥ 10 % of val.
B5 (P1) **AF-model clean-up.** AFDB full-length models carry low-pLDDT tails, signal peptides and disordered loops that can occupy or overhang the pocket, and constructs differ from the crystal (mutations, missing segments). Change: map residues through SIFTS, and trim residues with pLDDT < 50 that are not in secondary structure (one frozen rule, same for all methods). Report how often trimming touches pocket residues.
B6 (P1) **Physical sensibility of the AF arms.** A2 (side-chain repacking with the ligand) targets the documented gap: AF pocket backbone is about 1.3–1.5 Å, and the gap is mostly side chains. Prioritise it. A1 (softening) is cheap and sensible; scale softness by pLDDT and by side-chain vs backbone atoms (never soften the backbone). A3 (BioEmu/MD) addresses loop/backbone changes (P-loop, DFG, lids) but has the ensemble selection problem. Use a strain/population penalty and cap the ensemble at about 10 clustered members to keep it fast. A4 with the **query ligand** makes the pipeline per-ligand O(fold) (1–2 s/prediction), which conflicts with proteome-scale AFDB docking. Treat (b) the probe panel and the cofactor/ion co-fold (B4a) as the scalable AF mode, and (a) the query-ligand co-fold as an accuracy upper arm with cost reported. The 1m2q result (ligand had no effect) already argues for this.
B7 (P1) **Which scoring terms matter.** The literature says scoring, not sampling, limits accuracy (Vina native-pose failures 52 % vs Vinardo 33 %). Start from Vinardo, not Vina, as the default functional form. Expected-value order for extra terms: (1) ligand internal strain/torsional energy (also fixes PB-validity), (2) directional H-bond, (3) desolvation/buriedness, (4) metal coordination (if B4 stratum is large), (5) Coulomb with distance-dependent dielectric (low gain, risky with poor protonation). Fit the weights on decoys from ≥ 2 samplers (ours + Vina) and on **both holo and AF receptors** (AF-mode weights may differ: softer repulsion). Cap at ≤ 30 parameters and report the ablation per term.
B8 (P1) **Dimers.** For holo, use the biological assembly (rsyncPDB assemblies), not the asymmetric unit, and flag pockets formed by crystal contacts (ligand contacts only a symmetry mate not in the assembly). These are excluded from C4. For AF-mode dimers, AFDB is monomeric, so co-fold the assembly (Boltz-2 multimer with the stoichiometry from the assembly). Leakage dates apply.
B9 (P2) **Waters.** Remove all waters for the main runs (holo waters are ligand-informed). A conserved-water variant (waters kept only if present in ≥ 2 apo/other-ligand structures of the same UniProt) is optional and only for holo.
B10 (P2) **PB-validity as co-primary.** Report PB-valid & ≤ 2 Å next to plain ≤ 2 Å in every headline table. Softened/AF-mode receptors make it easy to produce clashing or strained poses that still pass RMSD; the PB checks against the *original* (unsoftened) receptor catch this.

## Summary
Main design changes: A1/A3/A4/A5/A8/A12 (guard scripts), A6 (filter val against test), A7 (val-select/val-confirm), A9 (2×2 factorial + Boltz-pose reference), B1 (pH 7.4 protonation), B3/B4 (cofactor/metal policy; UniProt-annotated cofactor co-folding as the scalable AF mode), B6 (move the query-ligand co-fold to an upper-bound arm).
